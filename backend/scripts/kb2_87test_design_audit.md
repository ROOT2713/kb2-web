## 测试集设计缺陷 (7大缺陷)

### 缺陷1: 55/87题缺少 RULE_PASS 定义 (致命)
无 RULE_PASS → 自动 UNCERTAIN。30个UNCERTAIN全是假失败。

### 缺陷2: 关键词匹配无通配/同义词
"2.5" ≠ "2.5m", "一年" ≠ "每年", "等保" ≠ "等级保护"

### 缺陷3: REJECT_TERMS 仅检查前500字
长回答开头说"未直接包含"后给实质内容也判 OVERREJECTION

### 缺陷4: NEEDS_REJECT 与防拒答指令矛盾
S组要求必须拒答, 但 system prompt 禁止说"未找到"

### 缺陷5: B组8题零 RULE_PASS
对比类回答(2887 vs 50174, A级vsB级等)没有评估标准

### 缺陷6: 8字和55字混为一谈
两种完全不同的根因合并为 ANSWER_TOO_SHORT

### 缺陷7: RULE_FAIL 不区分"质量问题"和"格式问题"
C02 1801字好回答因缺"2.5"判 RULE_FAIL

#### A2. 关键词匹配改为"宽松匹配" (高优先级)
```python
def kw_in_answer(kw, ans):
    """宽松关键词匹配: 子串匹配 + 数字通配 + 同义词"""
    # 数字通配: "2.5" 匹配 "2.5m", "2.5M", "2.5mm"
    # 同义词表
    SYNONYMS = {
        "一年": ["一年", "1年", "每年", "每一年", "一个自然年"],
        "半年": ["半年", "6个月", "六个月"],
        "等保": ["等保", "等级保护", "网络安全等级保护"],
        "2.5": ["2.5", "2.5m", "2.5M", "2.5米", "2.50"],
        "六类": ["六类", "6类", "cat6", "CAT6"],
        "超五类": ["超五类", "超5类", "cat5e", "CAT5e"],
    }
    if kw in SYNONYMS:
        return any(s in ans for s in SYNONYMS[kw])
    return kw in ans
```

### 方案 B (备选): 完全替代为 LLM-Judge

如果规则匹配太脆弱, 可用 LLM-Judge:

```python
def llm_judge(n, question, answer):
    """用 LLM 判断回答质量: 0-10分"""
    prompt = f"""你是问答质量评估专家。
问题: {question}
回答: {answer}

请判断该回答是否**基于知识库**正确回答了用户问题。
输出格式: PASS 或 FAIL(原因)"""
    ...
```

**优势**: 完美处理同义词、语义等价、格式差异
**劣势**: 需调用 LLM, 耗时增10x, 有额外成本, 结果不严格可复现

### 方案 C (折中): 规则++ + UNCERTAIN 白名单

在方案A基础上:
- 用 `LENIENT_MODE = True` 标志开启宽松模式

- 对 ≥800 字且来源数≥3 的 UNCERTAIN → 自动判 PASS
